# i18n / Text Externalization

Scope: every user-visible string (labels, button text, dialog titles, tooltips) in host and plugins.
Tracked initiative: issue #150 and its per-plugin sub-issues.

## Rule

No string literal directly on a Swing component. Every label/tooltip/title goes through a
properties-backed lookup, always with a literal default value (never the bare single-arg form) -
a missing key or corrupted properties file must show the default text, not throw
`MissingResourceException` out of a panel constructor.

## Host code (`src/main/java/...`)

Use the existing `io.github.astrapi69.mystic.crypt.Messages.getString(key, defaultValue)` +
`src/main/resources/ui/messages.properties`.

## Plugin code

Each plugin owns its text - it does not reach into the host's `ui.messages` bundle (a plugin
brings its own everything, architecture.md). Per plugin:

- A tiny `<Plugin>Messages` utility class (mirror `checksum-plugin`'s `ChecksumMessages`): a
  `ResourceBundle` field + one `getString(key, defaultValue)` method delegating to
  `ResourceBundleExtensions.getStringQuietly` (from `io.github.astrapi69:resourcebundle-core`,
  add as `compileOnly` + `testImplementation` in the plugin's `build.gradle` if not already
  present - already provided by the host at runtime, same as every other `compileOnly` library
  the plugin uses).
- Its own `plugins/<name>-plugin/src/main/resources/<name>/messages.properties`, packaged into
  the plugin zip automatically (same `src/main/resources` handling `pluginZip` already gives
  `plugin.properties`).

Do NOT add a shared cross-plugin `Messages` base class for this - the boilerplate per plugin is a
handful of lines, `ResourceBundleExtensions` already does the real work, and a shared abstraction
would recouple otherwise-independent plugin jars for no real benefit.

## Key naming

Dot-hierarchical, mirroring where the text sits in the UI:
`<scope>.<panel>.tooltip.<field>` (see `wizard.certificate.dates.tooltip.serial.number` or
`checksum.tooltip.compare.button`). No new top-level scope without a reason.
